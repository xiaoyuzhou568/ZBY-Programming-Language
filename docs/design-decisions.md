## 1. 项目定位与差异化论证（V0.1 基线）

### DD-001｜语言命名为 ZBY

- **状态**：基线已确定。
- **选择**：语言名为 **ZBY**；拟采用源代码扩展名 `.zby`。
- **命名依据**：ZBY 为项目语言的统一名称；课程题面中的语言名称不作为实现名称。
- **理由**：统一项目品牌、仓库、解释器命令、文件扩展名及文档称呼。
- **后续检查**：代码、README、演示和提交材料统一写 ZBY，不出现历史示例名造成混淆。

### DD-002｜面向初学者与 AI 编程 Agent 协作开发

- **状态**：基线已确定。
- **考察的方案**：A. 只面向初学者；B. 只面向 AI；C. 同时面向初学者与 AI 协作开发。
- **选择**：**C**。
- **理由**：人类需要易学、易读和易定位错误；AI 需要稳定语法、明确约束、可执行示例和可机器处理的反馈，两者有共同需求。
- **代价**：不能简单宣称“AI 友好”；必须通过 Agent 在只参考开发指南的情况下独立编写与修复程序来检验。
- **验证**：完整开发指南、错误诊断测试，以及由 Agent 使用 ZBY 开发不少于 200 行应用的过程记录。

### DD-003｜差异化不是“发明新关键字”，而是整套规则的组合

- **状态**：基线已确定。
- **考察的方案**：追求全新语法／直接模仿 Python 或 C／将已成熟的设计元素组成明确、精简、可诊断的体系。
- **选择**：第三种。
- **理由**：单独的类型标注、结构体、异常提示等机制并非 ZBY 原创；课程项目的价值在于有理有据的组合设计和完整可用的解释器。
- **代价**：需诚实说明与现有语言的相似性，不能把已有机制包装成技术发明。

### DD-004｜三个核心原则

- **状态**：基线已确定。
- **选择**：**Simplicity（简洁性）**、**Explicitness（明确性）**、**Explainability（可解释性）**。
- **对应设计行动**：
  1. 同一功能尽量一种标准写法；
  2. 明确类型、作用域与执行规则；
  3. 错误尽可能给出位置、类别、原因与合理的修复建议。
- **验证**：语法规范及测试覆盖、错误案例，以及最终应用的可读性和可运行性。

### DD-005｜评估并放弃“符合中文思维习惯”的核心路线

- **状态**：不纳入当前版本（作为探索记录保留）。
- **曾考察的层次**：中文关键字替换／中文语序的控制结构／更深入的自然语言式编程。
- **结论**：**不把全中文或中文自然语序作为 ZBY 的核心差异化**。
- **理由**：关键字翻译差异化有限；自然语言更灵活、更有歧义，与明确、统一、可预测的目标存在张力；还会提高词法/语法实现和测试成本，且已有中文编程语言探索。
- **保留的价值**：中文文档、中文注释、中文字符串、清楚的中文错误提示。
- **待核验**：是否允许**中文变量名**并未定稿；目前基本语法草案偏向 ASCII 标识符。见 L02。

### DD-006｜课程文档统一中文，程序技术标识保留英文

- **状态**：基线已确定。
- **选择**：README、项目介绍、设计规范、测试报告、Agent 指南、PPT 以中文说明；代码关键字、路径、函数名及 Git Commit 规范前缀使用英文。
- **理由**：便于课程表达、答辩与学习，同时维持工具链和语法的稳定性。
- **验证**：最终交付目录逐项检查语言风格。

### DD-007｜Git/GitHub 持续记录设计与实现过程

- **状态**：基线已确定。
- **选择**：每个关键工作阶段保留有意义的 Commit；正式里程碑另打 Tag。
- **理由**：老师要求保留完整 Git 历史；设计迭代和否决方案同样应留下证据。
- **注意**：`main` 分支的中间文档提交**不等于**发布完整版本；V0.2 完成前不打 `v0.2.0` 标签。

## 2. 语言基本形态与类型方案（V0.2 草案）

### DD-008｜统一的脚本式语法

- **状态**：方案已认可，待规范核验。
- **候选方案**：使用缩进控制代码块／使用大括号；强制 `main()`／直接运行顶层语句；语句换行结束／分号结束。
- **当前选择**：UTF-8 `.zby`；小写英文关键字；大括号代码块；普通语句以分号结尾；顶层语句可直接执行；单行 `//` 注释。
- **理由**：语句边界明确、语法规则统一，也容易实现 Lexer/Parser。
- **尚缺**：完整关键字、空白和空语句规则、字符串转义、数字字面量、顶层声明执行顺序。见 L01—L09、R07。

### DD-009｜变量显式声明类型且初始化，类型固定但值可修改

- **状态**：方案已认可，待规范核验。
- **方案比较**：自动推断 `let x = 1` 更短；显式 `let x: int = 1` 信息更多。
- **当前选择**：采用 `let name: Type = Expression;`，不支持省略类型；变量可重新赋值但不能换类型。
- **理由**：初学者和 Agent 可以直接读取类型约束，减少隐藏推断。
- **代价**：代码相对冗长。
- **示例**：`let age: int = 20;` 合法，`age = "twenty";` 非法。
- **待解决**：初始化表达式求值失败怎么办、重复声明/作用域及类型别名规则。见 F01—F13。

### DD-010｜禁止隐式数值转换

- **状态**：方案已认可，待规范核验。
- **曾考虑**：允许 `int + float` 中 `int` 自动提升；后转为全部显式转换。
- **当前选择**：`int + float` 不合法，需 `to_float(intValue) + floatValue`。
- **理由**：类型变化更可见、规则更统一。
- **代价**：增加类型转换代码，存在学习曲线。
- **测试方向**：混合运算必须报类型错误；显式转换后成功。
- **关联待决**：X02、T10。

### DD-011｜严格运行时类型检查优先，暂不要求完整静态检查器

- **状态**：方案已认可，待规范核验。
- **曾考虑**：独立 Semantic Analyzer 在执行前做完整静态检查。
- **调整理由**：课程要求是可运行解释器，完整静态类型分析会显著增加函数返回路径、复合类型、名称绑定的开发负担。
- **当前选择**：显式类型声明 + 严格运行时检查；静态类型检查模块作为后续增强，而非 V1.0 的必要依赖。
- **边界**：类型错误通常执行到对应语句才发生；不能再宣传为“运行前发现所有类型错误”。
- **关联待决**：X01、R01—R03。

### DD-012｜类型范围精简

- **状态**：方案已认可，待规范核验。
- **当前选择**：四种基本类型 `int`、`float`、`string`、`bool`；一维同质数组；用户定义 `struct`；仅作函数返回类型的 `void`。
- **不纳入 V1.0**：类继承、泛型、指针、手动内存管理、多线程、完整模块系统。
- **理由**：满足课程核心要求，同时控制实现规模。
- **边界**：结构体是否可嵌套、自引用、作为数组元素或函数返回值尚待正式规定。见 D04、D07、D10。

### DD-013｜结构体构造统一采用字段命名写法

- **状态**：暂定。
- **考察**：`Student("Alice", 20)` 与 `Student { name: "Alice", age: 20 }`。
- **当前倾向**：仅保留后一种；声明字段需要类型，创建时提供必要字段，修改时类型匹配。
- **理由**：字段名称直接可见，对 Agent 和初学者更明确；避免位置参数与字段顺序耦合。
- **尚缺**：字段顺序、重复/遗漏字段、结构体类型嵌套、构造表达式语法与错误规则。见 X03、D07—D10。

### DD-014｜数组和结构体的引用语义尚未冻结

- **状态**：**待决**。
- **曾提出的方案**：可变数组和结构体统一使用共享引用；基本类型按值传递。
- **优点**：动态数组操作、函数修改复合值较方便；便于用 Python 实现。
- **主要反对理由**：`b = a` 后修改 `b[0]` 会同时影响 `a[0]`，属于不直观的隐藏共享，与 Explicitness 有张力。
- **结论**：**不能因为先前草案写了“引用语义”就当作最终决定**。下一轮应比较值语义、共享引用和显式复制机制，检查函数参数、返回值的连带影响。
- **关联待决**：D01—D03、D09。

### DD-015｜错误诊断作为设计特色，不仅仅是异常消息

- **状态**：方案已认可，待规范核验。
- **当前方向**：报告错误类别、位置、期望/实际类型、原因；有可靠依据时给出修复建议。
- **考虑过的失败示例**：`let age: int = "hello";`。
- **取舍**：不要每次都机械建议 `to_int()`，因为任意字符串不一定可转换。
- **未定**：错误码、退出码、stdout/stderr、是否显示调用栈、错误后是否终止。见 R01—R08。

## 3. 数值、字符串与转换的深入斟酌（2026-11-25）

> 本节属于初步设计决策。相关规则仍需通过数值边界验证、一致性审查和解释器测试，不计为已实现功能。

### DD-016｜int 采用任意精度有符号整数

- **状态**：方案已认可，待规范核验。
- **备选**：固定 64 位（需溢出规则）／任意精度（受实际资源限制）。
- **选择**：任意精度。
- **理由**：对初学者不引入固定机器字长的额外负担，Python 实现方便。
- **代价**：大整数运算可能占用大量内存和时间；与 float 混合转换存在边界问题。
- **边界测试**：`999999999999999999999999 + 1` 得 `1000000000000000000000000`。
- **关联待决**：T01、T03、R08。

### DD-017｜float 表示方案：IEEE 754 binary64

- **状态**：方案已认可（表示格式）；**待决**（异常值完整语义）。
- **备选**：自行定义十进制精确小数／利用成熟的双精度二进制浮点数。
- **选择**：binary64，允许一般浮点舍入误差；不把 `0.1 + 0.2` 误认成精确的 0.3。
- **倾向的边界约束**：不提供 NaN、Infinity 字面量；使运算或转换产生非有限结果时报告数值错误。
- **尚缺**：溢出、下溢、负零、转换非有限值、除法边界、输出格式和具体错误类型。**不能仅凭本节就宣布已完全定义 float。**
- **关联待决**：T02、T08、T12。

### DD-018｜普通 `/` 除法：int/int 暂返回 float

- **状态**：暂定（主规则已讨论，极端行为未解决）。
- **备选**：整数截断除法／真除法返回浮点数／引入整数除法运算符。
- **当前倾向**：`10 / 4` 为 `2.5`（float）；除零时报错；不新增整数除法运算符。
- **理由**：符合初学者对普通除法的直觉，语法数量少。
- **代价**：大整数转双精度存在溢出和精度损失，`to_int(7 / 2)` 也不能代替精确的大整数整除。
- **必须补完**：超大整数、非有限结果、精度损失何时允许、是否最终需要 `//`（与注释冲突）或其他独立整数除法表示。见 T03—T04。

### DD-019｜负数取余采用除数符号规则

- **状态**：方案已认可，待规范核验。
- **备选**：结果跟随被除数符号／结果跟随除数符号。
- **选择**：采用 Python 整数取余语义，结果为 0 或与非零除数同号。
- **示例**：`7 % 3 = 1`、`-7 % 3 = 2`、`7 % -3 = -2`、`-7 % -3 = -1`。
- **尚缺**：取余零除数错误码和 `%` 只支持 int 的正式语法与诊断。
- **关联待决**：T05。

### DD-020｜字符串不可变，长度按 Unicode 码点

- **状态**：方案已认可，待规范核验。
- **备选**：可变字符串／不可变字符串；按 UTF-8 字节／按 Unicode 码点／按用户可见字素簇计长度。
- **选择**：字符串不可变；`len("你好") = 2`；重赋值整个变量合法，但 `name[0] = "M"` 非法。
- **理由**：行为清晰、使用 Python 字符串实现简单；不把中文 UTF-8 字节数误作文字长度。
- **代价**：由多个码点组合的可见字符可能被算为多个单位。
- **暂定扩展**：允许非负整数下标读取，越界报错，暂不支持切片。
- **关联待决**：T06—T07、I05。

### DD-021｜字符串转义采用小而固定的集合

- **状态**：方案已认可，待规范核验。
- **选择**：支持 `\\n`、`\\t`、`\\r`、`\\"`、`\\\\`；未知转义报词法错误；普通双引号字符串不可直接跨行。
- **理由**：满足常见文本输出，词法规则易于实现并具备确定性。
- **待补完**：文件末尾反斜杠、非 BMP 字符、源文件中的换行种类及报错列号。
- **关联待决**：L03—L04。

### DD-022｜显式转换函数的输入范围

- **状态**：方案已认可，待规范核验。
- **选择**：

| 来源类型 | `to_int` | `to_float` | `to_string` |
|---|---|---|---|
| int | 原值 | 转为浮点数，边界需检查 | 十进制字符串 |
| float | 向零截断，边界需检查 | 原值 | 浮点数字符串，格式待定 |
| string | 解析整数 | 解析浮点数 | 原值 |
| bool | 不支持 | 不支持 | `"true"` 或 `"false"` |
| 数组/结构体 | 不支持 | 不支持 | 暂不支持 |

- **明确示例**：`to_int(3.9)=3`；`to_int(-3.9)=-3`；`to_int("3.5")` 报转换错误；`to_float("3.5")=3.5`。
- **设计理由**：不依赖隐式转换，避免把 bool 误当数字。
- **尚缺**：字符串解析是否允许前后空格、指数写法、正号、前导零、无穷/NaN、空字符串、极大值；异常类型和错误位置。见 T09—T12。

### DD-023｜布尔与数值类型严格区分，第一版不提供 `to_bool()`

- **状态**：方案已认可，待规范核验。
- **早期备选**：沿用 Python 的 bool 与 int 关系，以及通用真值转换。
- **当前选择**：`true + 1` 非法；逻辑运算只接受 bool；显式转换函数不包含 `to_bool()`。
- **理由**：减少真值隐式转换，避免与明确性原则相冲突。
- **关联待决**：X05、T11、C01。

## 4. 尚未解决、不能“自动定稿”的事项

以下问题已有候选方案，但尚不满足正式定稿条件：

1. **数组/结构体的引用与复制**：最核心的待决事项；需要同时考虑参数传递、函数返回和初学者对共享可变状态的理解（D01—D03）。
2. **float 非有限值与整数真除法**：有精度和范围陷阱（T02—T04）。
3. **类型转换的字符串文法**：例如 `" 12 "`、`"+12"`、`"1e3"` 是否被接受（T10）。
4. **运算符的优先级、结合性与求值顺序**（E01—E09）。
5. **词法作用域、遮蔽、前向函数调用和递归返回路径**（F01—F13）。
6. **循环变量作用域、`break`/`continue`、短路求值细节**（C01—C06）。
7. **输入输出、格式化与错误退出协议**（I01—I07、R01—R08）。
8. **标识符是否允许中文**：中文语法核心路线已放弃，但标识符字符集仍需单独核准（L02）。

所有未决项详见 `docs/open-questions.md`。初步方案不等于完整的语言规范。

## 5. 设计选择与测试的关联（示例）

## 8. 复合类型与词法作用域（DD-024～DD-034）

### DD-024｜数组与结构体采用共享引用

- **已认可**：数组、结构体是可变复合对象。给另一变量赋值时，两个变量共享原对象，不会自动复制。
- **备选**：自动深拷贝的值语义；完全共享引用；共享引用并配套显式复制。
- **选择理由**：动态数组与复合对象可高效传递，适合应用编程；同时配套显式复制降低共享副作用的风险。
- **代价**：`let b: int[] = a; b[0] = 9;` 会改变 `a[0]`。开发指南必须解释共享与重绑定的区别。
- **验证**：共享数组元素修改可见；对局部变量重绑定不会改变外部变量的绑定。
- **待补**：复合对象的相等性与生命周期、错误时的副作用处理。

### DD-025｜提供显式 `clone()` 深拷贝

- **已认可**：`clone(value)` 用于数组和结构体，返回相同类型的独立复合对象；递归复制内部复合数据，不共享可变子对象。
- **备选**：完全不支持复制；赋值自动复制；显式浅拷贝；显式深拷贝。
- **选择理由**：复制行为在代码中可见，符合明确性原则，避免常见的意外共享。
- **代价**：深拷贝需要额外时间与内存。实现时应保留原对象内部共享子对象之间的对应关系（同一原对象在副本中仍映射到同一副本对象）。
- **验证**：修改克隆后嵌套数组，不改变原对象；检查副本内部别名关系。
- **待补**：克隆的异常/资源限制，复杂递归运行时结构的处理。

### DD-026｜函数复合参数采用共享传递（Pass by Sharing）

- **已认可**：函数形参是局部绑定；传入数组/结构体时共享对象。修改对象内部属性影响调用者；对形参重新赋值不会重新绑定调用者变量。
- **备选**：传值深拷贝；可修改调用者绑定的引用参数；共享传递。
- **选择理由**：不新增 `&`、指针或 `ref` 语法，却能满足数组修改需求。
- **代价**：需清楚区分 `a[0] = 99` 与 `a = [7, 8]`。
- **验证**：共享修改测试；形参重绑定测试；同一对象以两个形参传入测试。

### DD-027｜允许非递归结构体嵌套

- **已认可**：结构体字段可以是先定义的其他结构体类型、基本类型或合法的一维数组类型；禁止直接与间接递归的结构体类型依赖（含通过数组间接依赖）。
- **备选**：禁止所有嵌套；支持任意递归类型；仅支持非递归嵌套。
- **选择理由**：支持真实业务数据建模，避免引入 `null`、可选类型和递归构造终止问题。
- **代价**：暂不能直接表示链表等递归数据结构。
- **验证**：正常嵌套实例化；直接自引用与间接循环定义报错。
- **待补**：类型先声明后使用的详细规则、结构体构造的错误定位。

### DD-028｜允许函数返回复合类型

- **已认可**：函数返回类型可以是数组或结构体；返回时遵循共享引用语义，不会隐式深拷贝。
- **选择理由**：让函数能够构造并返回应用数据；避免与复合类型共享规则冲突。
- **验证**：返回数组后访问元素；多变量引用返回对象；用 `clone` 隔离。
- **待补**：缺少返回、返回类型错误、`void` 的具体执行规则。

### DD-029｜结构体按字段名称初始化

- **已认可**：采用 `Student { name: "Alice", score: 90.0 }` 形式；字段顺序不决定含义，每个声明字段必须恰好提供一次。
- **备选**：按位置参数的 `Student(...)`；按字段名的结构体字面量；两种形式并存。
- **选择理由**：字段含义显式可见，减少位置错误，也避免两套构造语法。
- **验证**：字段换序等价；缺少、重复、多余字段和类型不匹配报错。

### DD-030｜采用词法作用域

- **已认可**：名称解析依赖代码书写时的嵌套作用域结构，而不是调用栈上的动态调用者作用域。
- **备选**：动态作用域；词法作用域。
- **选择理由**：函数行为更可预测，与明确性和 AI 代码分析目标一致。
- **验证**：全局 `x=10`；`show()` 读取全局 `x`；在局部 `x=20` 的 `test()` 中调用 `show()`，仍输出 `10`。
- **待补**：局部与全局同名、初始化时绑定的解析、未声明名称诊断。

### DD-031｜允许内层变量遮蔽外层变量

- **已认可**：内层代码块可以声明与外层变量同名的局部变量。内层优先解析最近的声明；退出代码块后外层变量保持不变。同一作用域禁止重复声明。
- **备选**：完全不允许遮蔽；允许遮蔽。
- **选择理由**：兼容嵌套程序结构，减少全局命名限制。
- **代价**：可读性下降的风险；后续可提供可选警告而非禁止。
- **验证**：外层 80、内层 95，依次输出 95 与 80；同层重复声明报错。
- **待补**：形参遮蔽、结构体名/函数名是否可遮蔽。

### DD-032｜函数可以读写全局变量

- **已认可**：函数中的名称解析允许访问调用时已存在且可见的全局绑定；赋值应更新最近可见的既有绑定，除非当前块声明了同名局部变量。
- **备选**：全局只读；禁止访问全局；允许读写。
- **选择理由**：便于小型脚本与应用实现，降低第一版语法负担。
- **代价**：函数可能有副作用。规范和教程应强调共享状态风险。
- **验证**：全局 `count=0`，函数执行 `count=count+1` 后结果为 1。
- **待补**：变量尚未初始化、全局绑定在函数定义后但调用前声明、变量遮蔽与赋值歧义。

### DD-033｜函数先定义后调用

- **已认可**：解释执行按顺序建立顶层定义；调用一个尚未执行到定义语句的函数属于名称错误。函数在其定义建立后可以调用自身，从而支持递归。
- **备选**：先扫描所有函数定义、允许任意前向调用；顺序注册函数。
- **选择理由**：模型简单，顶层执行顺序容易解释。
- **代价**：函数定义顺序限制了程序组织；互相递归的函数须谨慎安排，V0.2 尚需明确其限制。
- **验证**：先定义再调用合法；先调用再定义报错；函数自递归能正确调用。
- **待补**：函数体中引用另一个后来定义的函数时，运行期如何解析（候选：实际调用时查找届时已注册的名称）。

### DD-034｜支持递归，暂不支持函数内定义函数

- **已认可**：顶层函数可以递归调用自身；不允许在函数体或普通代码块中再定义函数。
- **选择理由**：足以支持常见算法，作用域和闭包机制保持精简。
- **代价**：无法表达局部辅助函数和闭包。
- **验证**：阶乘等带终止条件的递归；非法嵌套函数定义报语法错误。
- **待补**：递归过深的错误反馈和资源限制。

### 关联待决事项

- **F12/F13/I06**：变量、结构体、函数、内置函数的名称冲突和遮蔽规则。

- **D09**：`clone()` 复制细节与失败语义。

## 9. 函数返回、命名与循环作用域（DD-035～DD-037）

### DD-035｜函数返回值与缺失返回行为

- **状态**：方案已认可，待规范与测试核验。
- **曾考虑的方案**：强制在执行前证明所有路径均返回；允许默认返回空值；执行时检查实际返回路径。
- **当前选择**：非 `void` 函数使用 `return 表达式;` 返回符合声明类型的值；`void` 函数允许 `return;` 提前结束，也允许执行至函数体末尾正常结束。
- **异常路径**：非 `void` 函数如果实际运行至末尾却没有返回值，报告运行时错误，不默默返回默认值。返回错误类型报告类型错误；函数外出现 `return` 必须拒绝，具体归为语法还是语义错误待解析器规则确定。
- **选择理由**：当前解释器采用运行时严格检查，避免第一版实现完整控制流返回路径的静态证明；缺失返回不被隐式掩盖。
- **代价**：未执行的分支中可能存在未被发现的返回错误；需使用分支覆盖测试。
- **正向测试**：非 `void` 返回正确类型、`void` 提前返回、`void` 自然结束。
- **反向测试**：非 `void` 走到函数末尾、返回类型错误、`void` 返回具体值、函数外 `return`。
- **仍待明确**：返回复合对象时遵循共享引用还是复制（现有 DD-028 倾向共享，需交叉检查）；诊断编号。

### DD-036｜名称冲突与遮蔽的基本规则

- **状态**：方案已认可，精确名称解析规则待规范核验。
- **候选**：变量、函数、结构体分离命名空间；允许任意名称覆盖；统一命名并限制遮蔽。
- **当前选择**：普通变量可以在内部词法作用域遮蔽外层普通变量；同一作用域的普通变量不能重复声明；用户定义变量不得与可见的函数、结构体类型、内置函数同名；用户定义函数或结构体也不得占用内置名称。
- **选择理由**：避免同一个名字在某处既代表值又代表函数或类型导致混淆，符合简洁性与明确性。
- **代价**：名称自由度受限；解释器需要维护名称类别信息。
- **测试**：同一块中重复声明报错；内部普通变量遮蔽外层普通变量合法；变量与函数/结构体/内置函数冲突报错。
- **仍待明确**：参数名是否能遮蔽全局普通变量（倾向允许）；函数参数间重名、参数与函数体顶层局部变量重名；前向定义时的冲突诊断时机；关键字和类型名是否为保留字。

### DD-037｜for 循环变量与循环体作用域

- **状态**：方案已认可，for 的完整语法和执行顺序尚待确定。
- **当前选择**：`for` 初始化部分声明的变量，在初始化、条件、迭代和循环体中可见；循环结束后不可见。每次循环体执行创建新的内层局部作用域；循环体内部声明的变量不在迭代表达式或下一次循环体中可见。
- **选择理由**：作用域边界清晰，不会泄漏循环计数器；每次循环可重新创建临时变量。
- **代价**：需要正确创建与销毁循环体作用域，且需明确更新语句的求值时机。
- **正向测试**：循环体访问计数器，循环体每次重声明临时变量合法。
- **反向测试**：循环外访问循环计数器、迭代语句访问循环体局部变量均报名称错误。
- **仍待明确**：初始化是否可为空、更新是否可为空；条件检查与更新的严格顺序；`break`/`continue` 的支持和效果。
