## 1. 项目定位与差异化论证（V0.1 基线）

### DD-001｜语言命名为 ZBY

- **状态**：基线已确定。
- **选择**：语言名为 **ZBY**；拟采用源代码扩展名 `.zby`。
- **命名依据**：ZBY 为项目语言的统一名称；课程题面中的语言名称不作为实现名称。
- **理由**：统一项目品牌、仓库、解释器命令、文件扩展名及文档称呼。
- **后续检查**：代码、README、演示和提交材料统一写 ZBY，不出现历史示例名造成混淆。

### DD-002｜面向初学者与 AI 编程 Agent 协作开发

- **状态**：基线已确定。
- **考察的方案**：A. 只面向初学者；B. 只面向 AI；C. 同时面向初学者与 AI 协作开发。
- **选择**：**C**。
- **理由**：人类需要易学、易读和易定位错误；AI 需要稳定语法、明确约束、可执行示例和可机器处理的反馈，两者有共同需求。
- **代价**：不能简单宣称“AI 友好”；必须通过 Agent 在只参考开发指南的情况下独立编写与修复程序来检验。
- **验证**：完整开发指南、错误诊断测试，以及由 Agent 使用 ZBY 开发不少于 200 行应用的过程记录。

### DD-003｜差异化不是“发明新关键字”，而是整套规则的组合

- **状态**：基线已确定。
- **考察的方案**：追求全新语法／直接模仿 Python 或 C／将已成熟的设计元素组成明确、精简、可诊断的体系。
- **选择**：第三种。
- **理由**：单独的类型标注、结构体、异常提示等机制并非 ZBY 原创；课程项目的价值在于有理有据的组合设计和完整可用的解释器。
- **代价**：需诚实说明与现有语言的相似性，不能把已有机制包装成技术发明。

### DD-004｜三个核心原则

- **状态**：基线已确定。
- **选择**：**Simplicity（简洁性）**、**Explicitness（明确性）**、**Explainability（可解释性）**。
- **对应设计行动**：
  1. 同一功能尽量一种标准写法；
  2. 明确类型、作用域与执行规则；
  3. 错误尽可能给出位置、类别、原因与合理的修复建议。
- **验证**：语法规范及测试覆盖、错误案例，以及最终应用的可读性和可运行性。

### DD-005｜评估并放弃“符合中文思维习惯”的核心路线

- **状态**：不纳入当前版本（作为探索记录保留）。
- **曾考察的层次**：中文关键字替换／中文语序的控制结构／更深入的自然语言式编程。
- **结论**：**不把全中文或中文自然语序作为 ZBY 的核心差异化**。
- **理由**：关键字翻译差异化有限；自然语言更灵活、更有歧义，与明确、统一、可预测的目标存在张力；还会提高词法/语法实现和测试成本，且已有中文编程语言探索。
- **保留的价值**：中文文档、中文注释、中文字符串、清楚的中文错误提示。
- **待核验**：是否允许**中文变量名**并未定稿；目前基本语法草案偏向 ASCII 标识符。见 L02。

### DD-006｜课程文档统一中文，程序技术标识保留英文

- **状态**：基线已确定。
- **选择**：README、项目介绍、设计规范、测试报告、Agent 指南、PPT 以中文说明；代码关键字、路径、函数名及 Git Commit 规范前缀使用英文。
- **理由**：便于课程表达、答辩与学习，同时维持工具链和语法的稳定性。
- **验证**：最终交付目录逐项检查语言风格。

### DD-007｜Git/GitHub 持续记录设计与实现过程

- **状态**：基线已确定。
- **选择**：每个关键工作阶段保留有意义的 Commit；正式里程碑另打 Tag。
- **理由**：课程要求保留完整 Git 历史；设计迭代和否决方案同样应留下证据。
- **注意**：`main` 分支的中间文档提交**不等于**发布完整版本；V0.2 完成前不打 `v0.2.0` 标签。

## 2. 语言基本形态与类型方案（V0.2 草案）

### DD-008｜统一的脚本式语法

- **状态**：方案已认可，待规范核验。
- **候选方案**：使用缩进控制代码块／使用大括号；强制 `main()`／直接运行顶层语句；语句换行结束／分号结束。
- **当前选择**：UTF-8 `.zby`；小写英文关键字；大括号代码块；普通语句以分号结尾；顶层语句可直接执行；单行 `//` 注释。
- **理由**：语句边界明确、语法规则统一，也容易实现 Lexer/Parser。
- **尚缺**：完整关键字、空白和空语句规则、字符串转义、数字字面量、顶层声明执行顺序。见 L01—L09、R07。

### DD-009｜变量显式声明类型且初始化，类型固定但值可修改

- **状态**：方案已认可，待规范核验。
- **方案比较**：自动推断 `let x = 1` 更短；显式 `let x: int = 1` 信息更多。
- **当前选择**：采用 `let name: Type = Expression;`，不支持省略类型；变量可重新赋值但不能换类型。
- **理由**：初学者和 Agent 可以直接读取类型约束，减少隐藏推断。
- **代价**：代码相对冗长。
- **示例**：`let age: int = 20;` 合法，`age = "twenty";` 非法。
- **待解决**：初始化表达式求值失败怎么办、重复声明/作用域及类型别名规则。见 F01—F13。

### DD-010｜禁止隐式数值转换

- **状态**：方案已认可，待规范核验。
- **曾考虑**：允许 `int + float` 中 `int` 自动提升；后转为全部显式转换。
- **当前选择**：`int + float` 不合法，需 `to_float(intValue) + floatValue`。
- **理由**：类型变化更可见、规则更统一。
- **代价**：增加类型转换代码，存在学习曲线。
- **测试方向**：混合运算必须报类型错误；显式转换后成功。
- **关联待决**：X02、T10。

### DD-011｜严格运行时类型检查优先，暂不要求完整静态检查器

- **状态**：方案已认可，待规范核验。
- **曾考虑**：独立 Semantic Analyzer 在执行前做完整静态检查。
- **调整理由**：课程要求是可运行解释器，完整静态类型分析会显著增加函数返回路径、复合类型、名称绑定的开发负担。
- **当前选择**：显式类型声明 + 严格运行时检查；静态类型检查模块作为后续增强，而非 V1.0 的必要依赖。
- **边界**：类型错误通常执行到对应语句才发生；不能再宣传为“运行前发现所有类型错误”。
- **关联待决**：X01、R01—R03。

### DD-012｜类型范围精简

- **状态**：方案已认可，待规范核验。
- **当前选择**：四种基本类型 `int`、`float`、`string`、`bool`；一维同质数组；用户定义 `struct`；仅作函数返回类型的 `void`。
- **不纳入 V1.0**：类继承、泛型、指针、手动内存管理、多线程、完整模块系统。
- **理由**：满足课程核心要求，同时控制实现规模。
- **后续进展**：DD-027 已允许非递归结构体嵌套，DD-028 已允许函数返回复合类型；结构体数组仍须在正式类型语法中核验。

### DD-013｜结构体构造统一采用字段命名写法

- **状态**：历史方案已由 DD-029 确认。
- **考察**：`Student("Alice", 20)` 与 `Student { name: "Alice", age: 20 }`。
- **历史倾向及后续决定**：采用 `Student { name: "Alice", age: 20 }`。DD-029 已确认按名称初始化，字段必须恰好提供一次；字段顺序不影响语义。
- **理由**：字段名称直接可见，对 Agent 和初学者更明确；避免位置参数与字段顺序耦合。
- **后续进展**：字段顺序与缺漏/重复规则已由 DD-029 规定；嵌套结构体及递归限制见 DD-027；诊断格式仍待确定。

### DD-014｜数组和结构体的引用语义（早期方案比较）

- **状态**：历史待决记录；现已由 DD-024～DD-026 确定共享引用、显式深拷贝与共享传递。
- **曾提出的方案**：可变数组和结构体统一使用共享引用；基本类型按值传递。
- **优点**：动态数组操作、函数修改复合值较方便；便于用 Python 实现。
- **主要反对理由**：`b = a` 后修改 `b[0]` 会同时影响 `a[0]`，属于不直观的隐藏共享，与 Explicitness 有张力。
- **后续结论**：比较值语义、默认共享和显式复制后，采用默认共享引用、`clone()` 深拷贝以及函数共享传递（DD-024～DD-026）。原有的意外共享风险仍需通过文档和测试予以控制。
- **关联待决**：D01—D03、D09。

### DD-015｜错误诊断作为设计特色，不仅仅是异常消息

- **状态**：方案已认可，待规范核验。
- **当前方向**：报告错误类别、位置、期望/实际类型、原因；有可靠依据时给出修复建议。
- **考虑过的失败示例**：`let age: int = "hello";`。
- **取舍**：不要每次都机械建议 `to_int()`，因为任意字符串不一定可转换。
- **后续进展**：DD-044 已确认运行时错误立即终止、无回滚，且诊断输出到 stderr；错误码、退出码、调用栈格式和资源错误仍待确定。见 R01—R08。

## 3. 数值、字符串与转换的深入斟酌（2026-11-25）

> 本节属于初步设计决策。相关规则仍需通过数值边界验证、一致性审查和解释器测试，不计为已实现功能。

### DD-016｜int 采用任意精度有符号整数

- **状态**：方案已认可，待规范核验。
- **备选**：固定 64 位（需溢出规则）／任意精度（受实际资源限制）。
- **选择**：任意精度。
- **理由**：对初学者不引入固定机器字长的额外负担，Python 实现方便。
- **代价**：大整数运算可能占用大量内存和时间；与 float 混合转换存在边界问题。
- **边界测试**：`999999999999999999999999 + 1` 得 `1000000000000000000000000`。
- **关联待决**：T01、T03、R08。

### DD-017｜float 表示方案：IEEE 754 binary64

- **状态**：方案已认可（表示格式）；**待决**（异常值完整语义）。
- **备选**：自行定义十进制精确小数／利用成熟的双精度二进制浮点数。
- **选择**：binary64，允许一般浮点舍入误差；不把 `0.1 + 0.2` 误认成精确的 0.3。
- **倾向的边界约束**：不提供 NaN、Infinity 字面量；使运算或转换产生非有限结果时报告数值错误。
- **尚缺**：溢出、下溢、负零、转换非有限值、除法边界、输出格式和具体错误类型。**不能仅凭本节就宣布已完全定义 float。**
- **关联待决**：T02、T08、T12。

### DD-018｜普通 `/` 除法：int/int 暂返回 float

- **状态**：暂定（主规则已讨论，极端行为未解决）。
- **备选**：整数截断除法／真除法返回浮点数／引入整数除法运算符。
- **当前倾向**：`10 / 4` 为 `2.5`（float）；除零时报错；不新增整数除法运算符。
- **理由**：符合初学者对普通除法的直觉，语法数量少。
- **代价**：大整数转双精度存在溢出和精度损失，`to_int(7 / 2)` 也不能代替精确的大整数整除。
- **必须补完**：超大整数、非有限结果、精度损失何时允许、是否最终需要 `//`（与注释冲突）或其他独立整数除法表示。见 T03—T04。

### DD-019｜负数取余采用除数符号规则

- **状态**：方案已认可，待规范核验。
- **备选**：结果跟随被除数符号／结果跟随除数符号。
- **选择**：采用 Python 整数取余语义，结果为 0 或与非零除数同号。
- **示例**：`7 % 3 = 1`、`-7 % 3 = 2`、`7 % -3 = -2`、`-7 % -3 = -1`。
- **尚缺**：取余零除数错误码和 `%` 只支持 int 的正式语法与诊断。
- **关联待决**：T05。

### DD-020｜字符串不可变，长度按 Unicode 码点

- **状态**：方案已认可，待规范核验。
- **备选**：可变字符串／不可变字符串；按 UTF-8 字节／按 Unicode 码点／按用户可见字素簇计长度。
- **选择**：字符串不可变；`len("你好") = 2`；重赋值整个变量合法，但 `name[0] = "M"` 非法。
- **理由**：行为清晰、使用 Python 字符串实现简单；不把中文 UTF-8 字节数误作文字长度。
- **代价**：由多个码点组合的可见字符可能被算为多个单位。
- **暂定扩展**：允许非负整数下标读取，越界报错，暂不支持切片。
- **关联待决**：T06—T07、I05。

### DD-021｜字符串转义采用小而固定的集合

- **状态**：方案已认可，待规范核验。
- **选择**：支持 `\\n`、`\\t`、`\\r`、`\\"`、`\\\\`；未知转义报词法错误；普通双引号字符串不可直接跨行。
- **理由**：满足常见文本输出，词法规则易于实现并具备确定性。
- **待补完**：文件末尾反斜杠、非 BMP 字符、源文件中的换行种类及报错列号。
- **关联待决**：L03—L04。

### DD-022｜显式转换函数的输入范围

- **状态**：方案已认可，待规范核验。
- **选择**：

| 来源类型 | `to_int` | `to_float` | `to_string` |
|---|---|---|---|
| int | 原值 | 转为浮点数，边界需检查 | 十进制字符串 |
| float | 向零截断，边界需检查 | 原值 | 浮点数字符串，格式待定 |
| string | 解析整数 | 解析浮点数 | 原值 |
| bool | 不支持 | 不支持 | `"true"` 或 `"false"` |
| 数组/结构体 | 不支持 | 不支持 | 暂不支持 |

- **明确示例**：`to_int(3.9)=3`；`to_int(-3.9)=-3`；`to_int("3.5")` 报转换错误；`to_float("3.5")=3.5`。
- **设计理由**：不依赖隐式转换，避免把 bool 误当数字。
- **尚缺**：字符串解析是否允许前后空格、指数写法、正号、前导零、无穷/NaN、空字符串、极大值；异常类型和错误位置。见 T09—T12。

### DD-023｜布尔与数值类型严格区分，第一版不提供 `to_bool()`

- **状态**：方案已认可，待规范核验。
- **早期备选**：沿用 Python 的 bool 与 int 关系，以及通用真值转换。
- **当前选择**：`true + 1` 非法；逻辑运算只接受 bool；显式转换函数不包含 `to_bool()`。
- **理由**：减少真值隐式转换，避免与明确性原则相冲突。
- **关联待决**：X05、T11、C01。

## 4. 早期待决问题记录（后续状态以新决策和待决清单为准）

以下为 2026-11-25 的阶段性待决事项，部分已由 DD-024～DD-048 形成后续决定；现行状态以 `docs/open-questions.md` 为准：

1. **数组/结构体的引用与复制**：最核心的待决事项；需要同时考虑参数传递、函数返回和初学者对共享可变状态的理解（D01—D03）。
2. **float 非有限值与整数真除法**：有精度和范围陷阱（T02—T04）。
3. **类型转换的字符串文法**：例如 `" 12 "`、`"+12"`、`"1e3"` 是否被接受（T10）。

## 8. 复合类型与词法作用域（DD-024～DD-034）

### DD-024｜数组与结构体采用共享引用

- **已认可**：数组、结构体是可变复合对象。给另一变量赋值时，两个变量共享原对象，不会自动复制。
- **备选**：自动深拷贝的值语义；完全共享引用；共享引用并配套显式复制。
- **选择理由**：动态数组与复合对象可高效传递，适合应用编程；同时配套显式复制降低共享副作用的风险。
- **代价**：`let b: int[] = a; b[0] = 9;` 会改变 `a[0]`。开发指南必须解释共享与重绑定的区别。
- **验证**：共享数组元素修改可见；对局部变量重绑定不会改变外部变量的绑定。
- **待补**：复合对象的相等性与生命周期、错误时的副作用处理。

### DD-025｜提供显式 `clone()` 深拷贝

- **已认可**：`clone(value)` 用于数组和结构体，返回相同类型的独立复合对象；递归复制内部复合数据，不共享可变子对象。
- **备选**：完全不支持复制；赋值自动复制；显式浅拷贝；显式深拷贝。
- **选择理由**：复制行为在代码中可见，符合明确性原则，避免常见的意外共享。
- **代价**：深拷贝需要额外时间与内存。实现时应保留原对象内部共享子对象之间的对应关系（同一原对象在副本中仍映射到同一副本对象）。
- **验证**：修改克隆后嵌套数组，不改变原对象；检查副本内部别名关系。
- **待补**：克隆的异常/资源限制，复杂递归运行时结构的处理。

### DD-026｜函数复合参数采用共享传递（Pass by Sharing）

- **已认可**：函数形参是局部绑定；传入数组/结构体时共享对象。修改对象内部属性影响调用者；对形参重新赋值不会重新绑定调用者变量。
- **备选**：传值深拷贝；可修改调用者绑定的引用参数；共享传递。
- **选择理由**：不新增 `&`、指针或 `ref` 语法，却能满足数组修改需求。
- **代价**：需清楚区分 `a[0] = 99` 与 `a = [7, 8]`。
- **验证**：共享修改测试；形参重绑定测试；同一对象以两个形参传入测试。

### DD-027｜允许非递归结构体嵌套

- **已认可**：结构体字段可以是先定义的其他结构体类型、基本类型或合法的一维数组类型；禁止直接与间接递归的结构体类型依赖（含通过数组间接依赖）。
- **备选**：禁止所有嵌套；支持任意递归类型；仅支持非递归嵌套。
- **选择理由**：支持真实业务数据建模，避免引入 `null`、可选类型和递归构造终止问题。
- **代价**：暂不能直接表示链表等递归数据结构。
- **验证**：正常嵌套实例化；直接自引用与间接循环定义报错。
- **待补**：类型先声明后使用的详细规则、结构体构造的错误定位。

### DD-028｜允许函数返回复合类型

- **已认可**：函数返回类型可以是数组或结构体；返回时遵循共享引用语义，不会隐式深拷贝。
- **选择理由**：让函数能够构造并返回应用数据；避免与复合类型共享规则冲突。
- **验证**：返回数组后访问元素；多变量引用返回对象；用 `clone` 隔离。
- **待补**：缺少返回、返回类型错误、`void` 的具体执行规则。

### DD-029｜结构体按字段名称初始化

- **已认可**：采用 `Student { name: "Alice", score: 90.0 }` 形式；字段顺序不决定含义，每个声明字段必须恰好提供一次。
- **备选**：按位置参数的 `Student(...)`；按字段名的结构体字面量；两种形式并存。
- **选择理由**：字段含义显式可见，减少位置错误，也避免两套构造语法。
- **验证**：字段换序等价；缺少、重复、多余字段和类型不匹配报错。

### DD-030｜采用词法作用域

- **已认可**：名称解析依赖代码书写时的嵌套作用域结构，而不是调用栈上的动态调用者作用域。
- **备选**：动态作用域；词法作用域。
- **选择理由**：函数行为更可预测，与明确性和 AI 代码分析目标一致。
- **验证**：全局 `x=10`；`show()` 读取全局 `x`；在局部 `x=20` 的 `test()` 中调用 `show()`，仍输出 `10`。
- **待补**：局部与全局同名、初始化时绑定的解析、未声明名称诊断。

### DD-031｜允许内层变量遮蔽外层变量

- **已认可**：内层代码块可以声明与外层变量同名的局部变量。内层优先解析最近的声明；退出代码块后外层变量保持不变。同一作用域禁止重复声明。
- **备选**：完全不允许遮蔽；允许遮蔽。
- **选择理由**：兼容嵌套程序结构，减少全局命名限制。
- **代价**：可读性下降的风险；后续可提供可选警告而非禁止。
- **验证**：外层 80、内层 95，依次输出 95 与 80；同层重复声明报错。
- **待补**：形参遮蔽、结构体名/函数名是否可遮蔽。

### DD-032｜函数可以读写全局变量

- **已认可**：函数中的名称解析允许访问调用时已存在且可见的全局绑定；赋值应更新最近可见的既有绑定，除非当前块声明了同名局部变量。
- **备选**：全局只读；禁止访问全局；允许读写。
- **选择理由**：便于小型脚本与应用实现，降低第一版语法负担。
- **代价**：函数可能有副作用。规范和教程应强调共享状态风险。
- **验证**：全局 `count=0`，函数执行 `count=count+1` 后结果为 1。
- **待补**：变量尚未初始化、全局绑定在函数定义后但调用前声明、变量遮蔽与赋值歧义。

### DD-033｜函数先定义后调用

- **已认可**：解释执行按顺序建立顶层定义；调用一个尚未执行到定义语句的函数属于名称错误。函数在其定义建立后可以调用自身，从而支持递归。
- **备选**：先扫描所有函数定义、允许任意前向调用；顺序注册函数。
- **选择理由**：模型简单，顶层执行顺序容易解释。
- **代价**：函数定义顺序限制了程序组织。DD-038 已明确：相互递归所需函数在首次实际调用前注册完毕即可。
- **验证**：先定义再调用合法；先调用再定义报错；函数自递归能正确调用。
- **后续进展**：DD-038 已确认函数调用发生时解析届时已注册的名称；尚未注册则报名称错误。

### DD-034｜支持递归，暂不支持函数内定义函数

- **已认可**：顶层函数可以递归调用自身；不允许在函数体或普通代码块中再定义函数。
- **选择理由**：足以支持常见算法，作用域和闭包机制保持精简。
- **代价**：无法表达局部辅助函数和闭包。
- **验证**：阶乘等带终止条件的递归；非法嵌套函数定义报语法错误。
- **待补**：递归过深的错误反馈和资源限制。

### 关联待决事项

- **F12/F13/I06**：变量、结构体、函数、内置函数的名称冲突和遮蔽规则。

- **D09**：`clone()` 复制细节与失败语义。
- **F04/F05**：定义时与调用时全局名称可见性的边界。

## 9. 函数返回、命名与循环作用域（DD-035～DD-037）

### DD-035｜函数返回值与缺失返回行为

- **状态**：方案已认可，待规范与测试核验。
- **曾考虑的方案**：强制在执行前证明所有路径均返回；允许默认返回空值；执行时检查实际返回路径。
- **当前选择**：非 `void` 函数使用 `return 表达式;` 返回符合声明类型的值；`void` 函数允许 `return;` 提前结束，也允许执行至函数体末尾正常结束。
- **异常路径**：非 `void` 函数如果实际运行至末尾却没有返回值，报告运行时错误，不默默返回默认值。返回错误类型报告类型错误；函数外出现 `return` 必须拒绝，具体归为语法还是语义错误待解析器规则确定。
- **选择理由**：当前解释器采用运行时严格检查，避免第一版实现完整控制流返回路径的静态证明；缺失返回不被隐式掩盖。
- **代价**：未执行的分支中可能存在未被发现的返回错误；需使用分支覆盖测试。
- **正向测试**：非 `void` 返回正确类型、`void` 提前返回、`void` 自然结束。
- **反向测试**：非 `void` 走到函数末尾、返回类型错误、`void` 返回具体值、函数外 `return`。
- **仍待明确**：返回复合对象时遵循共享引用还是复制（现有 DD-028 倾向共享，需交叉检查）；诊断编号。

### DD-036｜名称冲突与遮蔽的基本规则

- **状态**：方案已认可，精确名称解析规则待规范核验。
- **候选**：变量、函数、结构体分离命名空间；允许任意名称覆盖；统一命名并限制遮蔽。
- **当前选择**：普通变量可以在内部词法作用域遮蔽外层普通变量；同一作用域的普通变量不能重复声明；用户定义变量不得与可见的函数、结构体类型、内置函数同名；用户定义函数或结构体也不得占用内置名称。
- **选择理由**：避免同一个名字在某处既代表值又代表函数或类型导致混淆，符合简洁性与明确性。
- **代价**：名称自由度受限；解释器需要维护名称类别信息。
- **测试**：同一块中重复声明报错；内部普通变量遮蔽外层普通变量合法；变量与函数/结构体/内置函数冲突报错。
- **后续进展**：DD-039 已明确参数遮蔽全局普通变量、重复参数和同层冲突；关键字及内置名称的完整清单、诊断时机仍待确定。

### DD-037｜for 循环变量与循环体作用域

- **状态**：方案已认可，for 的完整语法和执行顺序尚待确定。
- **当前选择**：`for` 初始化部分声明的变量，在初始化、条件、迭代和循环体中可见；循环结束后不可见。每次循环体执行创建新的内层局部作用域；循环体内部声明的变量不在迭代表达式或下一次循环体中可见。
- **选择理由**：作用域边界清晰，不会泄漏循环计数器；每次循环可重新创建临时变量。
- **代价**：需要正确创建与销毁循环体作用域，且需明确更新语句的求值时机。
- **正向测试**：循环体访问计数器，循环体每次重声明临时变量合法。
- **反向测试**：循环外访问循环计数器、迭代语句访问循环体局部变量均报名称错误。
- **后续进展**：DD-040 已规定三个部分不可省略及执行顺序，DD-041 已规定 `break`/`continue`；更新语法及异常边界仍需 EBNF 核验。

## 10. 函数注册、形参、循环与跳转（DD-038～DD-041）

### DD-038｜函数注册及调用时名称解析

- **状态**：设计方案已确定；具体错误码和执行器测试尚待实现。
- **方案比较**：① 在执行前扫描并注册所有函数，允许任意位置调用；② 仅在遇到定义语句时注册，并在定义时验证函数体中的所有名称；③ 按顶层执行顺序注册，在执行函数体时解析其可见名称。
- **决定**：采用③。函数定义语句执行时注册函数对象，不执行函数体；调用发生时，该函数必须已注册；函数体中其他函数名在相应调用实际发生时解析。因此允许两个函数在首次调用前均已注册的相互递归，但不允许先调用尚未注册的函数。函数内读取全局普通变量亦遵循执行时已初始化和可见的原则。
- **理由**：保持顶层程序的顺序执行模型，同时允许自递归及满足时序要求的相互递归，不引入预扫描或提前全局注册。
- **代价**：程序结果依赖顶层定义与调用的执行顺序；名称不存在时，错误可能延迟到相应函数体执行才被触发。
- **成功测试**：定义 `first`（内部调用 `second`），之后定义 `second`，最后调用 `first`；相互递归函数均注册后调用。
- **失败测试**：在 `first` 定义之前直接调用 `first`；首次调用某函数时，函数体中执行到尚未注册的 `second`。
- **剩余边界**：函数类型标注中的结构体名称何时解析；全局变量初始化顺序与错误优先级；前向结构体类型是否允许（F04、R07、D10）。

### DD-039｜函数参数名称与作用域遮蔽

- **状态**：设计方案已确定；与保留关键字表相关的边界尚待核对。
- **备选方案**：① 全部参数名不得与任何外部名称重复；② 与全局变量同名时自动修改全局绑定；③ 参数属于函数局部作用域，可遮蔽全局普通变量，但同层不允许重复声明。
- **决定**：采用③。两个形参不得重名；形参可与全局普通变量同名，优先解析形参；形参与函数体最外层的普通变量声明不得重名；更深一层代码块可遮蔽普通变量；形参不得与函数名、结构体类型名或内置名称冲突。
- **理由**：统一 DD-030、DD-031、DD-036 的词法作用域和名称冲突原则，避免调用方状态被参数绑定无意改变。
- **代价**：名称检查需区分普通变量与函数/类型/内置名称，且需要把形参和函数体最外层定义视作同一层级。
- **成功测试**：全局 `score=80`，以 `score=95` 作为形参调用函数，在函数中打印95，调用结束后全局仍为80；更深内层块声明 `score` 合法。
- **失败测试**：重复形参；形参与函数体顶层局部变量重名；形参与内置函数名冲突。
- **剩余边界**：内置名称与保留字完整列表；用户函数及结构体声明的名称冲突检查时机（L01、F12、I06）。

### DD-040｜for 循环的语法、执行顺序与作用域

- **状态**：设计方案已确定；完整 EBNF 与解析器测试待实现。
- **方案比较**：① 可省略初始化、条件或更新的宽松三段式；② `for-each` 形式；③ 所有三部分必须出现的 C 风格三段式。
- **决定**：采用③。标准形式为 `for (let i: int = 0; i < limit; i = i + 1) { ... }`。初始化采用显式变量声明，仅执行一次；每次循环先检查布尔条件，条件为 false 则退出；条件为 true 时创建当轮循环体作用域并执行循环体；正常结束后执行更新赋值并再次检查条件。循环初始化变量在整个循环内可见、退出后不可见，循环体每轮建立新的块作用域。
- **理由**：控制结构无可省略分支，解释器和开发者可依靠单一、清楚的执行顺序。
- **代价**：不适合所有循环形式；需要没有计数器的循环时可用 `while`。
- **成功测试**：打印0、1、2；初始化只执行一次；逐轮重新定义循环体局部变量；循环条件一开始为 false 时循环体和更新均不执行。
- **失败测试**：省略初始化/条件/更新；条件不是 `bool`；循环结束后访问初始化变量；更新表达式访问循环体局部变量。
- **剩余边界**：更新部分目前限定为普通变量赋值语句的无末尾分号形式；复合位置赋值、多表达式更新是否需要支持，留至 E05 与 E06；循环内错误中断按未来运行机制统一（C02、E05、R03）。

### DD-041｜break 与 continue

- **状态**：设计方案已确定；控制流实现与测试待完成。
- **曾考虑**：V1.0 禁止二者以压缩语言；仅支持 `break`；同时支持 `break` 和 `continue`。
- **决定**：两者都纳入 V1.0，仅可用于循环内部。`break;` 立即退出最近一层 `for`/`while`，跳过该轮剩余语句；`continue;` 跳过当前轮剩余语句，在 `for` 中先执行更新再重新检查条件，在 `while` 中直接检查条件。嵌套循环中的两种跳转只作用于最近的一层循环。
- **理由**：对实际应用（查找、筛选、提前退出）有明确价值，语义简单，避免为绕过限制写冗余标志变量。
- **代价**：解释器需实现并正确传播循环控制信号，防止跨越函数边界；控制流测试需要覆盖嵌套循环和提前退出。
- **成功测试**：`for i=0..4` 中跳过1、遇4退出，输出0、2、3；嵌套循环中的 `break` 仅退出内层；`for` 内 `continue` 会触发更新。
- **失败测试**：循环外使用 `break` 或 `continue`；不允许通过函数调用把循环控制信号传递到外层调用者循环。
- **剩余边界**：具体错误类别、源码位置信息、与 `return` 以及运行时错误优先级的一致性（C04、R01、R03）。

### 本组决策关联

- DD-038 细化 DD-033 的“先定义后调用”，消除其相互递归的歧义。
- DD-039 补充 DD-031、DD-036 的参数遮蔽与名称冲突边界。
- DD-040 细化 DD-037 的循环变量作用域，确定三段式的常规执行顺序。
- DD-041 将 C04 从“暂不支持”修订为“支持”，并明确 `for` 中 `continue` 的更新步骤。
- 新决策不意味着尚未定义的运算符、语法字面量、错误格式或解释器实现已经完成。

## 11. 表达式求值与错误终止（DD-042～DD-044）

### DD-042｜子表达式按语法结构从左到右求值

- **状态**：方案已认可，待正式语法及黑盒测试验证。
- **备选方案**：不规定操作数求值顺序；允许实现自由调整；按语法树的操作数与书写顺序固定求值。
- **决定**：采用确定的从左到右求值。对于二元运算，先求左侧，再求右侧；函数实参、数组字面量元素、结构体命名字段的初始化表达式均按照源码出现顺序求值。运算符优先级与结合性先确定语法树，随后才根据语法树确定实际求值步骤，不能将“从左到右”理解为忽略优先级。
- **赋值边界**：在赋值语句中先求值并定位左侧赋值目标，再求右侧表达式，之后执行类型和有效性检查及写入。嵌套下标、字段访问的细节参见 DD-047；短路运算是本规则的特殊情况（DD-043）。
- **理由**：涉及函数调用、副作用时程序行为仍可由源码推导，符合明确性原则。
- **代价**：实现不可自由重排可能具有副作用的计算；需要记录复杂赋值位置的求值时机。
- **成功测试**：`first()+second()` 输出日志先 first 再 second；`f(a(), b())` 按书写顺序调用；数组元素与结构体字段初始化副作用按书写顺序发生。
- **边界测试**：左侧求值失败时不执行右侧；下标定位失败不执行赋值右侧；同一赋值期间出现对象别名和局部变量重新绑定时不意外改变已选定的目标对象。

### DD-043｜and/or 严格布尔短路求值

- **状态**：方案已认可，待正式语法及黑盒测试验证。
- **备选方案**：两个操作数总是执行；允许通用真值转换；只对 `bool` 采用短路逻辑。
- **决定**：采用最后一种。首先求左操作数并检查其结果为 `bool`；`false and RHS` 与 `true or RHS` 不计算 RHS；其他情况下执行 RHS 且检查其结果为 `bool`。逻辑表达式结果只能是 `bool`。
- **解释范围**：表达式 RHS 仍必须通过执行前的词法、语法分析；对于未执行 RHS，不发生运行时求值及其运行时类型、名称、数值错误。这与 DD-011 不要求完整静态类型检查的决定一致。
- **理由**：避免不必要的副作用和错误，提高条件表达式可读性。
- **代价**：未被执行的错误分支可能直到之后某条路径运行时才被发现。
- **成功测试**：`false and (1 / 0 > 0.0)` 得 `false`；`true or (1 / 0 > 0.0)` 得 `true`；短路 RHS 的副作用不发生。
- **边界测试**：`true and 123` 在 RHS 执行时报告类型错误；`false and 123` 在无完整静态类型检查的模型中得到 `false`；左侧非 `bool` 必须报错。

### DD-044｜执行前完整语法分析；运行时错误立即终止且不回滚

- **状态**：方案已认可，错误码、调用栈和退出码等输出协议待定。
- **备选方案**：边解析边执行；执行出错后尝试恢复并继续；执行前完整词法、语法分析，运行时发生首个错误即终止。
- **决定**：采用第三种。任何词法或语法失败都阻止开始顶层执行；运行期间发生错误后，立即停止整个程序，报告首个实际发生的运行时错误并输出到 stderr，不继续后续语句；已经完成的标准输出及共享对象修改不自动回滚。V1.0 不提供 `try/catch` 异常恢复机制。
- **控制信号区别**：正常的 `return`、`break`、`continue` 不是运行时错误；不允许跨函数边界传播循环跳转信号，具体非法上下文的诊断阶段仍需规定。
- **理由**：执行过程可预测，错误处理成本较低，适合第一版解释器。
- **代价**：运行中断后无法自动恢复；先前的副作用不可撤销；可能需要多次运行才能排查不同错误路径。
- **成功测试**：运行时除零前的输出保留，错误之后不执行；递归调用深处发生错误时全局终止；标准输出和错误输出分流。
- **边界测试**：源文件末尾含语法错误时，前面的 `print` 一律不执行；已有共享数组修改在后续错误发生后不回滚；短路未执行的非法运算不触发运行时错误。
- **待补**：解析阶段错误数量、错误码、退出码、调用栈和资源不足行为（R01～R08）。

## 12. 运算符、优先级与赋值（DD-045～DD-048）

### DD-045｜精简运算符集合与操作数类型

- **状态**：方案已认可；除法数值极端边界另由 DD-018 和 T02～T04 处理。
- **备选方案**：开放宽泛的隐式类型转换及运算符重载；提供多个拼接与比较函数；限定操作数类型并在必要时显式转换。
- **决定**：支持算术 `+ - * / %`、大小比较 `< <= > >=`、相等判断 `== !=`、逻辑 `and or not`、一元负号 `-`，以及函数调用 `()`、下标 `[]`、字段访问 `.` 和分组括号。`+` 允许同类型数值加法与 `string + string` 连接，不允许 `string + int`。`%` 只支持 `int` 对 `int`，遵循 DD-019 的余数符号规则。数值大小比较和相等比较需要同一数值类型；`string` 与 `bool` 分别只支持同类型的 `==`/`!=`。跨类型比较不隐式转换。数组、结构体在 V1.0 不支持直接 `==`/`!=`。
- **理由**：操作类型表明确，能满足基础计算及常见字符串处理，同时控制语义和解析器复杂度。
- **代价**：需要显式转换；不提供数组与结构体的直接相等性比较；`+` 具有数值和字符串两种用途。
- **成功测试**：`"a" + "b"` 得 `"ab"`；`-7 % 3` 得 2；`3 == 3` 得 true；`"a" != "b"` 得 true。
- **失败测试**：`"a" + 1`、`3 == 3.0`、`true + 1`、`5.5 % 2.0`、`[1] == [1]` 均报类型错误或对应不支持的操作错误。
- **待补**：完整数值运算类型矩阵，浮点特殊值、极大整数除法及格式化规则；浮点比较特殊边界仍归 T02、T08 管理。

### DD-046｜运算符优先级、结合性与禁止连续比较

- **状态**：方案已认可，EBNF 与解析器测试待完成。
- **备选方案**：所有运算符统一优先级；完全沿用某一现有语言；采用精简的固定优先级表。
- **决定**：采用由高到低的顺序：① 后缀调用 `()`、下标 `[]`、字段访问 `.`；② 一元负号 `-`；③ `* / %`；④ `+ -`；⑤ `< <= > >=`；⑥ `== !=`；⑦ `not`；⑧ `and`；⑨ `or`。后缀链从左到右构建；算术二元运算与逻辑 `and`、`or` 左结合；一元负号、`not` 右结合。比较与相等判断不允许无括号的连续链式写法（包括混合链，如 `a < b == true`），需要分别比较并用逻辑运算组合或增加显式括号。
- **理由**：尊重常见算术结构，同时降低链式比较和逻辑取反的歧义；`not 3 < 5` 解释为 `not (3 < 5)`。
- **代价**：不能直接写 `1 < x < 10`；无括号混合比较的解析器规则需明确检查。
- **成功测试**：`2 + 3 * 4` 为 14；`20 - 5 - 3` 为 12；`true or false and false` 为 true；`not 3 < 5` 为 false；`(1 < x) == true` 允许按类型规则求值。
- **失败测试**：`1 < x < 10`、`a < b == true`、`a == b == c` 因禁止链式比较被拒绝。带括号的显式分组另行按普通表达式规则验证。
- **一致性要求**：DD-042 指定已经形成的语法树内部的实际求值顺序，不能覆盖本条优先级与结合性。

### DD-047｜赋值是语句而非表达式

- **状态**：方案已认可；复杂赋值目标的规范和测试待补。
- **备选方案**：赋值返回值并允许连续赋值；普通变量赋值为语句但容许链式赋值；所有赋值均为语句。
- **决定**：采用第三种。普通变量、数组元素、结构体字段及由变量起始的复合访问路径可作为赋值目标（如 `x = 1;`、`nums[0] = 1;`、`student.age = 18;`、`students[0].age = 18;`）。不支持将赋值嵌入其他表达式，也不支持 `a = b = 5;`；V1.0 暂不允许 `get_student().age = 18;` 直接作为赋值目标。字符串不可变，因此字符串下标不可赋值。
- **求值边界**：执行赋值先求值并定位目标对象、下标及字段，先校验可判定的类型与边界，再按 DD-042 求右侧；右侧求值结束后重新检查目标对象和位置的有效性及待写入值的类型，之后写入。若右侧改变变量绑定，不应意外重定向已经定位的目标对象；若右侧改变数组长度导致原下标无效则报告运行时错误。
- **理由**：将状态变化置于明确的语句中，降低隐式副作用，易于调试与审查。
- **代价**：不能链式赋值，也不能在条件中嵌入赋值；直接修改调用结果字段时需临时变量。
- **成功测试**：普通变量重新赋值、数组元素修改、结构体字段修改，以及 `students[0].age` 等复合路径修改。
- **失败测试**：`a = b = 5;`、`if (x = 1) {}`、`get_student().age = 1;`、`name[0] = "A";`；左侧索引越界时右侧带副作用函数不被调用。
- **待补**：赋值目标的完整 EBNF、只读字符串链式位置、结构体字段计算时机及相关错误类别。

### DD-048｜简写赋值及自增自减暂缓引入，保留扩展意向

- **状态**：V1.0 基线暂不实现；后续扩展优先复评，并非永久否决。
- **备选方案**：第一版同时支持 `++ -- += -=`；只支持 `+= -=`；仅提供普通赋值语句，在核心解释器稳定后再扩展简写。
- **当前决定**：先采用普通赋值形式（如 `x = x + 1;`）；V1.0 暂不支持 `x++`、`--x`、`x += 1`、`x -= 1`。项目明确保留引入这些简写的意向，后续根据应用代码需求和解析器稳定性复评，尤其优先评估 `+=` 与 `-=`。
- **选择理由**：暂时控制语法范围，先完成核心解释器和必要测试；允许后续按实际使用频率调整，而非永久封禁。
- **代价**：常见计数和累加语句稍长；未获得复合赋值的简洁性。
- **扩展前必须明确**：`++`/`--` 是仅限语句还是也可用于表达式；是否允许前缀与后缀形式；复合赋值下标/字段目标是否只计算一次；如何与 DD-047 的“赋值不是表达式”保持一致；可能的副作用与类型检查顺序。
- **当前成功测试**：`x = x + 1;` 正常运行。
- **当前拒绝测试**：`x++;`、`--x;`、`x += 1;`、`x -= 1;` 在 V1.0 的语法中被拒绝。
- **后续复评指标**：实际 ZBY 应用中自增和复合赋值出现的需求频率；支持新语法所增加的解析及回归测试成本；是否降低表达歧义。

## 14. 数值边界与显式转换（DD-049～DD-051）

### DD-049｜精确整数除法采用 `int_div(a, b)`

- **状态**：方案已认可，待规范及测试验证。
- **备选方案**：① 仅保留 `/`，接受任意精度 `int` 转 `float` 后的精度限制；② 让 `int / int` 直接返回整数；③ 引入整数除法运算符；④ 保留 `/` 的真除法方向，并提供内置函数 `int_div(a, b)`。
- **决定**：采用④。`int_div` 接受两个 `int`，要求除数非零，返回任意精度 `int`，使用向负无穷取整；与 `%` 共同满足 `a == int_div(a,b)*b + a%b`。不使用 `//` 作为除法运算符，因为 `//` 已作为单行注释。
- **理由**：补足任意精度整数的精确整除能力，同时不扩大运算符词法集合，且与 DD-019 的负数取余规则统一。
- **代价**：增加一个内置函数；用户需要分辨普通除法、整除及求余。
- **成功测试**：`int_div(7,3)==2`、`int_div(-7,3)==-3`、`int_div(7,-3)==-3`、`int_div(-7,-3)==2`；使用大整数检查商、余数恒等式。
- **失败测试**：除数为零；任一参数不是 `int`；参数数量错误。
- **仍待解决**：DD-018 的 `int/int -> float` 为既有方向，极大整数转 binary64 时的溢出、舍入及错误时机尚未完全定稿；本决策不将普通 `/` 的边界自动定稿。

### DD-050｜float 使用有限的 IEEE 754 binary64 值

- **状态**：方案已认可，精确格式化和计算边界待规范验证。
- **备选方案**：① 允许 NaN/Infinity 作为常规值继续传播；② 采用高精度十进制浮点表示；③ 使用 binary64，但要求可见计算结果为有限值。
- **决定**：采用③。浮点除零报错；计算、解析或转换导致非有限结果时报数值错误；源代码不提供 NaN/Infinity 字面量。允许正常舍入、下溢到零和 `-0.0`；比较中 `-0.0 == 0.0` 为真。
- **理由**：避免非有限值延迟传播，使数值错误更容易定位；保留成熟的 binary64 实现方式。
- **代价**：某些数值算法无法使用 Infinity/NaN 作为哨兵值；极端运算直接终止程序。
- **成功测试**：普通有限值运算；舍入到零；`-0.0 == 0.0`；正常有限范围的显式转换。
- **失败测试**：`1.0/0.0`、超大浮点乘法导致溢出、`to_float("nan")`、转换数值溢出。
- **仍待解决**：极大整数 `/` 的计算途径、最低次正规数与舍入边界、`-0.0` 的输出形式、具体数值错误码与浮点打印算法。

### DD-051｜字符串数值转换使用严格格式

- **状态**：方案已认可，`to_float` 接受整数形式字符串等细节需统一验证。
- **备选方案**：① 自动去除两端空白并容忍宽松数字格式；② 完全继承宿主 Python 的转换语法；③ 规定独立、严格的 ZBY 字符串数字文法。
- **决定**：采用③。`to_int("42")`、`to_int("-42")`、`to_int("+42")` 有效；`to_int(" 42 ")`、`to_int("042")`、`to_int("3.5")` 无效。`to_float("3.5")`、`to_float("1e3")` 有效；`to_float("nan")` 无效。格式错误报告转换错误；转换后非有限值遵循 DD-050。
- **理由**：数字解析不依赖宿主语言偶然接受的写法；用户必须显式处理不规范输入。
- **代价**：输入处理更严格，通常需要另外执行字符串预处理。
- **成功测试**：带正负号的合法整数字符串、小数和指数浮点字符串。
- **失败测试**：首尾空白、前导零、整数解析小数、空字符串、非有限值字符串。
- **仍待解决**：`to_float("3")` 等整数形式浮点字符串的处理、浮点指数与符号的完整 EBNF、数值转换错误类别、极大值及精度策略。`to_int("+42")` 有效不自动意味着源码 `+42` 合法，源码一元正号尚未纳入 DD-045。

## 15. 词法及语句边界（DD-052～DD-057）

### DD-052｜严格十进制数字字面量

- **状态**：方案已认可，待词法规范和边界测试验证。
- **备选方案**：① 宽松支持 `01`、`.5`、`1.` 等形式；② 严格十进制且允许指数；③ 仅普通整数与带点小数，不支持指数。
- **决定**：采用②。整数使用十进制 `0` 或不以零开头的非零数字串；浮点写法包含完整整数与小数部分，或带 `e/E` 及可选指数符号的科学计数法。`1e3` 为 `float`；`01`、`.5`、`1.`、`1e`、`0xFF` 不合法。负号为独立的一元运算符而非数字 Token 的组成部分。
- **理由**：扫描规则明确；支持常见科学计数形式，减少歧义。
- **代价**：放弃多种常见简写和非十进制字面量。
- **成功测试**：`0`、`42`、`0.5`、`1e3`、`1.2E+5`、`-42`。
- **失败测试**：`01`、`.5`、`1.`、`1e`、`0xFF`；检查不能将非法连续数字串切成多个合法 Token。
- **仍待解决**：词法格式合法但数值超出有限 binary64 时，具体的报错阶段与错误分类；字符串转换文法的最终对应关系。

### DD-053｜ASCII 标识符且区分大小写

- **状态**：方案已认可，Unicode 标识符为将来扩展评估项。
- **备选方案**：① 允许 Unicode 字母（包括中文）构成名称；② 第一版限定为 ASCII 名称。
- **决定**：采用②。标识符匹配 `[A-Za-z_][A-Za-z0-9_]*`，区分大小写；中文与其他 Unicode 字符可出现在字符串和注释中，但不能作为标识符。
- **理由**：简化词法类别、兼容性和名称一致性检查，避免 Unicode 规范化产生的名称歧义。
- **代价**：中文使用者不能直接使用中文命名。
- **成功测试**：`student_age2`、`Score` 和 `score` 可为不同名称。
- **失败测试**：`2score`、`学生年龄`；同一作用域中完全同名的重复声明。
- **仍待解决**：关键字及内置名称冲突的具体诊断阶段。

### DD-054｜固定保留字与预留内置名称

- **状态**：方案已认可；内置函数行为不因名称预留而自动认可。
- **备选方案**：① 允许覆盖内置函数或类型名称；② 上下文动态解释关键字；③ 固定语法保留词和不可覆盖的内置名称。
- **决定**：采用③。保留20个关键词/类型名称：`let fn return struct if else while for break continue true false and or not int float string bool void`。预留内置函数名：`print input len push pop clone to_int to_float to_string int_div`。这些内置名不可被用户定义变量、函数或类型覆盖；内置名本身可作为普通调用目标 Token 分类处理。
- **理由**：消除名称混淆，使词法规则与 DD-036、DD-039 的名称冲突原则一致。
- **代价**：限制可用标识符集合；新内置函数的引入需要审查名称兼容性。
- **成功测试**：所有保留词正确分类；普通用户标识符合法使用。
- **失败测试**：`let print: int = 1;`、`let if: int = 1;` 及用户函数/类型占用预留名。
- **仍待解决**：`push`、`pop`、`len`、`print`、`input` 的具体行为仍取决于 DD-060、DD-063、DD-064 等未认可候选；名称注册与解析器错误定位须在 EBNF 中统一。

### DD-055｜文件编码、空白和注释

- **状态**：方案已认可，边界位置统计待测试。
- **备选方案**：① 允许多种源文件编码和注释形式；② 固定 UTF-8 与单行注释、明确位置计算。
- **决定**：采用②。源文件采用 UTF-8，文件开头可忽略 UTF-8 BOM；将空格、Tab 和换行作为语法外空白，接受 LF 与 CRLF；仅 `//` 引入行末注释。行号和列号从1开始，列号按 Unicode 码点计数，Tab 视为一个码点。字符串内的 `//` 不是注释。
- **理由**：词法分析器稳定，可精确定位错误；保留中文注释支持。
- **代价**：不支持块注释，列号不是终端显示的视觉列宽。
- **成功测试**：带 BOM 文件、LF/CRLF、中文注释、字符串中的 `https://`。
- **失败测试**：无效 UTF-8、注释外非法字符；测试多码点行及 Tab 后的列号。
- **仍待解决**：严格允许哪些 Unicode 空白、CR 单独作为换行的行为以及换行标准化如何进入列位置诊断。

### DD-056｜双引号字符串与五种转义

- **状态**：方案已认可，扫描器边界待验证。
- **备选方案**：① 同时支持单引号、跨行字符串和多种 Unicode 转义；② 只支持双引号单行字符串与固定转义集合。

- **理由**：容易实现，兼顾基本文本编写需求。
- **代价**：长字符串、Unicode 转义及单引号字符串暂不支持。
- **成功测试**：`"你好"`、含 `\n` 和 `\"` 的字符串。
- **失败测试**：`\q`、未闭合双引号、原始字符串跨行、文件末尾单独反斜杠。
- **仍待解决**：与 DD-055 的 CRLF 位置统计、转义展开后码点长度的测试对应。

### DD-057｜分号、空文件和空块

- **状态**：方案已认可，EBNF 待编写。
- **备选方案**：① 换行结束语句或允许末尾省略分号；② 允许单独分号作为空语句；③ 强制普通语句以分号结尾，允许空源文件、空块，不支持独立空语句。
- **决定**：采用③。普通语句包括文件最后一条普通语句，均需以 `;` 结束；`{}` 及空 `.zby` 文件合法；单独 `;` 不合法；函数定义、`if/while/for` 等以代码块收尾的结构不追加分号。`for` 头部的分号属于循环语法，并非独立空语句。
- **理由**：语句边界明确，解析器结构一致。
- **代价**：显式分号增加代码书写量。
- **成功测试**：空文件、空块、带分号的声明、无尾随分号的函数定义和循环块。
- **失败测试**：文件末尾省略分号、单独 `;`、块后冗余空语句。
- **仍待解决**：正式 EBNF 中结构体字段声明和函数调用语句的分号位置。

### 候选 DD-064｜input 的一行文本输入和 EOF

- **候选**：`input()` 或 `input(prompt: string)` 读取一行，保留普通空格并去除尾部行结束符，返回 `string`；EOF 报输入错误；空行返回空字符串。

- **取舍理由**：把 I/O 和类型转换分开，符合显式转换原则。
- **潜在代价**：用户需处理空白及文本转换错误，EOF 不可当作普通空行。
- **测试草案**：空行、包含中文、含首尾空格、提示文字、CRLF、EOF、错误参数类型及数量。
- **待确认**：提示的 stdout 刷新、终端与文件重定向的字节编码、异常名和提示是否换行。

### 候选 DD-065｜内置函数参数检查与求值时机

- **候选**：调用内置函数先校验参数个数，再从左到右求值实参且检查已求值参数的类型；校验失败后不继续执行后续参数，全部合规后执行函数操作。
- **备选方案**：先求值全部实参再检查参数；允许各内置函数自行确定检查时机；统一签名验证和短路错误策略。
- **取舍理由**：错误时序一致，避免明显无效实参之后产生不必要的副作用。
- **潜在代价**：需要在调用前明确内置函数签名；与用户函数调用的时序关系必须统一。
- **测试草案**：参数数量错误时任何实参副作用不发生；第一个参数错误时跳过第二个参数；全部正确时按顺序调用；共享数组修改可见。
- **待确认**：用户自定义函数是否遵循完全相同的提前参数数量/类型检查策略，以及诊断发生时机。

## 17. 错误诊断、控制流与运行边界（DD-066～DD-071）

### DD-066｜统一的解释性错误诊断

- **状态**：方案已认可，错误码及格式细节待规范验证。
- **备选方案**：① 直接透传宿主 Python 的异常文本；② ZBY 自定义统一错误对象和源码级诊断格式。
- **决定**：采用②。错误报告至少包含错误类别、ZBY 文件名及行列号、明确原因；当有可靠信息时显示期望/实际类型和源码定位提示。初版错误分类覆盖 `LexError`、`SyntaxError`、`NameError`、`TypeError`、`IndexError`、`ZeroDivisionError`、`ValueError`、`ArgumentError`、`InputError`、`ResourceError` 等预定类别。
- **理由**：隐藏实现语言内部细节，提升学习者和自动化开发工具对错误的理解与定位能力。
- **代价**：Lexer/Parser/AST 及运行时必须保留足够的源码位置信息，集中维护错误对象和渲染规则。
- **成功测试**：变量赋值类型错误包含文件名、行列号和期望/实际类型；跨函数错误定位到真正失败语句。
- **失败/边界测试**：错误中不泄漏 Python traceback；非法 UTF-8、未知名称、除零、非法转换等分别具有稳定分类。
- **仍待解决**：每类错误的正式编号、诊断中中文/英文使用约定、源码片段与多码点列号的呈现、候选 DD-060 的空数组 `pop()` 错误是否采用 `ValueError`。

### DD-067｜首个错误报告与执行前结构检查

- **状态**：方案已认可，诊断阶段须在规范中准确命名。
- **备选方案**：① 解析时尝试错误恢复并收集多条错误；② 解析阶段首错即停；③ 将非法 `return/break/continue` 延迟到对应语句运行时才检查。
- **决定**：语法及必要的结构上下文检查在执行前完成，报告首次发现的词法/语法/结构性错误，禁止开始执行；运行时继续遵循 DD-044 的首个实际错误立即终止规则。循环外 `break/continue`、函数外 `return` 等非法控制结构在执行前拒绝。
- **理由**：避免解析错误引发成串误报，确保有结构错误的文件不会部分执行；结构上下文检查不要求完整静态类型分析。
- **代价**：需要解析时跟踪函数/循环上下文，并重置函数内部循环层级，防止错误允许跨函数 `break`。
- **成功测试**：完整有效程序正常执行；合法嵌套循环和函数 `return` 正确解析。
- **失败测试**：`print("Start"); break;` 不打印 Start；函数外 `return;` 和在函数中但循环外 `continue;` 执行前拒绝；源文件末尾存在语法错误时前面程序不执行。
- **仍待解决**：解析阶段“首错”在多处错误同时存在时具体扫描顺序；静态上下文与运行时名称/类型检查的边界。

### DD-068｜显示简化函数调用栈

- **状态**：方案已认可，截断格式与调用帧细节待规范验证。
- **备选方案**：① 只报告最底层错误位置；② 输出完整宿主语言堆栈；③ 输出与 ZBY 源代码对应的简化调用栈。
- **决定**：采用③。运行时错误报告函数调用路径，包括各 ZBY 函数调用及相应源码位置，必要时包含顶层调用入口。递归调用栈过长时允许截断，并明确说明省略的调用帧数量。
- **理由**：递归和跨函数错误更容易定位，避免泄漏宿主 Python 栈信息。
- **代价**：需要维护 ZBY 调用帧及其调用点信息。
- **成功测试**：顶层→函数A→函数B 产生错误时显示调用顺序与错误位置；正常递归返回不输出调用栈。
- **失败/边界测试**：深递归错误能截断且不误报省略帧数量；错误调用路径不出现 Python 内部函数名。
- **仍待解决**：调用栈是最近调用在前还是在后、截断上限及标示格式。

### DD-069｜输出通道与进程退出状态

- **状态**：方案已认可，终端编码细节待规范验证。
- **备选方案**：① 所有输出共用 stdout，不使用退出码区分错误；② 按错误种类使用大量不同退出码；③ stdout/stderr 分离，0/1 表示成功/失败。
- **决定**：采用③。程序正常结束退出码为0；词法/语法错误、运行时错误、脚本不存在或命令行用法错误退出码为1。程序标准输出写 stdout；诊断写 stderr；失败前已经输出的内容不回滚，符合 DD-044。
- **理由**：适合命令行自动化测试及外部调用，减少退出码规则数量。
- **代价**：测试时需要同时核验两个输出流，具体字符编码与刷新时机需要稳定规定。
- **成功测试**：正常脚本退出0且 stderr 为空；标准输出准确包含程序 `print` 的文本。
- **失败测试**：词法/运行时错误退出1且诊断仅在 stderr，错误后不继续输出；文件不存在退出1。
- **仍待解决**：stdin/stdout/stderr 默认编码、重定向与平台换行；`input` 提示未换行时刷新策略属于候选 DD-064。

### DD-070｜while 语义与独立函数调用语句

- **状态**：方案已认可，EBNF 待规范核验。
- **备选方案**：① `while` 可包含额外 `else` 或省略显式块；② 标准 `while (boolExpression) { block }`；③ 允许任意表达式独立成语句；④ 仅允许函数调用独立成语句。
- **决定**：`while (condition) { ... }` 每轮先求条件并要求 `bool`，条件为真时创建本轮的块作用域并执行循环体，遵循 DD-041 的 `break/continue`，不支持 `while ... else`。函数调用可独立构成语句，调用结果（即使非 `void`）可以丢弃；任意纯计算表达式如 `10 + 20;` 不作为独立语句。
- **理由**：保持控制结构一致，兼容无返回值和有副作用函数调用，不引入通用表达式语句。
- **代价**：调用结果被忽略可能掩盖使用者的逻辑错误；拒绝无用表达式语句，语法稍有限制。
- **成功测试**：`while` 计数器迭代；循环体逐轮局部作用域；`while` 内 `continue` 重新判断条件；普通函数调用单独成语句。
- **失败测试**：`while (1) {}` 因非 `bool` 条件报错；`while ... else` 语法拒绝；`10 + 20;` 拒绝。
- **仍待解决**：仅函数调用或通过字段/下标取得的可调用对象是否可成为调用语句；当前函数定义不支持一等函数对象，须与 EBNF 保持一致。

### DD-071｜函数递归深度与资源限制

- **状态**：方案已认可，默认限制数值尚待核定。
- **备选方案**：① 直接依赖 Python 的递归深度及原生异常；② 无调用深度限制；③ 解释器设置可配置的 ZBY 函数调用深度上限。
- **决定**：采用③。递归过深时报告 `ResourceError` 并终止，按照 DD-068 输出必要调用栈；上限可配置。曾提出默认256层，现保留为待测试的初始建议值，不在没有实现验证时冻结。暂不对所有合法 `while` 循环设置固定的最大迭代次数。
- **理由**：防止无限递归使宿主解释器异常崩溃，同时给使用者可理解的错误。
- **代价**：额外调用帧管理、资源预算配置、宿主实现与虚拟调用深度之间的换算。
- **成功测试**：正常较浅递归可以执行；配置不同深度上限后行为可预测。
- **失败/边界测试**：无限递归在达到上限时报 `ResourceError`，而不是原生 Python 异常；调用栈截断显示正常。
- **仍待解决**：默认上限具体数值；配置接口；用户中断和其他资源不足情形的错误协议。
