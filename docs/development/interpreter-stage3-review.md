# ZBY Interpreter 第三阶段 · 错误诊断与端到端验证记录

## 1. 目的与基线

以 Interpreter 第二阶段276项通过的回归测试为基线，增强对 ZBY 源码错误的定位能力，并采用独立 Python 子进程验证命令行层面的真实行为。实现范围限定为诊断、必要的错误位置修复、跨模块回归和示例应用，不改变已认可的语言语义。

## 3. 诊断输出契约（本阶段实现）

1. 第一行为 `文件名:行:列: 错误类别: 原因`。行、列从1开始，列号按 Unicode 码点计数。
2. 当源文件可解码且位置有效时，显示对应源代码行及插入符号标记。单行运行时错误跨度用于显示更长定位区间。
3. 对有明确期望/实际类型的错误，显示单独的 `期望类型`、`实际类型` 字段。
4. 若运行时错误保留了 ZBY 调用栈，则按外层到内层显示；超过12帧时仅保留前2帧和最后10帧，并说明省略数量。
5. 诊断只写入 stderr；已有程序输出保留在 stdout；错误退出码为1，正常退出为0。
6. 无法恢复源文本（例如非法 UTF-8）时仍报告原始词法错误的位置和原因，不伪造源码片段。

显示布局及12帧数量属于目前的原型实现约定，并非所有细节已经冻结为 ZBY V1.0 规范。

## 4. 运行时发现并修复的问题

先前变量声明初始化失败时，`declare()` 用整条变量声明节点作类型检查位置，例如 `let x: int = "bad";` 的错误被报告在第1列，而不是字符串的起始位置。本阶段为 `declare()` 增加可选的类型检查位置，仅在变量声明时传入初始化表达式节点；函数参数声明及名称冲突仍按原有节点报告。

对应的黑盒测试覆盖 ASCII、中文、Tab、CRLF 与开头 BOM，防止源码位置退化。

## 5. 代表性黑盒测试矩阵

| 类别 | 场景 | 预期 |
|---|---|---|
| 正常执行 | 完整成绩记录程序 | 退出0，UTF-8 stdout 精确匹配，stderr 为空 |
| 输入 | `input(prompt)` 接收中文与空行 | 提示先输出；返回字符串；空行与 EOF 不混淆 |
| 前置拒绝 | 源文件末尾存在非法词法/语法或非法 `break` | 执行前报错，前面的 `print` 不输出 |
| 类型与定位 | `int` 接收 `string` | stderr 报 TypeError、源码行、指针、期望与实际类型 |
| 跨函数错误 | 函数内除零 | stdout/stderr 正确，ZBY 调用路径包含调用者与被调者 |
| 资源限制 | 递归达到指定深度上限 | ResourceError，退出1，不泄露宿主 traceback |
| 副作用 | 参数个数错/第一实参类型错 | 不执行应跳过的实参，不打印其副作用 |
| 运行时错误 | 数组越界发生在一次输出之后 | 保留先前输出，不执行错误后代码 |
| 字节兼容 | UTF-8、LF、CRLF 源码、非法 UTF-8 | 类型与位置符合预期；stdout 统一 LF |
| 待决语法 | 空结构体及尾随逗号 | 当前默认 Parser 拒绝，测试记录为保守模式行为，不作为正式禁令 |
