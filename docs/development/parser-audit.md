# ZBY V0.2 Parser / AST 实现审查记录

> 状态：可运行的语法原型，尚未实现解释器。此处的测试属于实际 Parser/Lexer 运行结果，不代表运行时语义通过。

## 1. 依据与覆盖

- 词法：原有 Lexer，DD-008、DD-021、DD-052～DD-056。
- 表达式：DD-042～DD-047；其中关系运算和相等运算采用两层递归下降，拒绝未加括号的混合链。
- 声明与控制流：DD-009、DD-029～DD-041、DD-057、DD-067、DD-070、DD-075～DD-077。
- AST：保留词法源位置、整数/浮点数字面量原始文本、字符串解码结果以及显式括号节点。

## 2. 优先级与歧义

| 输入 | AST/拒绝预期 | 原因 |
|---|---|---|
| `2 + 3 * 4` | `+(2, *(3,4))` | 乘法高于加法 |
| `not a < b` | `not (<(a,b))` | not 低于关系运算 |
| `a or b and c` | `or(a, and(b,c))` | and 高于 or |
| `(a < b) == true` | 合法 | 显式分组 |
| `a < b == true` | 拒绝 | 不允许未加括号混合比较 |
| `a == b < c` | 拒绝 | 不允许未加括号混合比较 |
| `a < b < c` | 拒绝 | 不允许连续关系比较 |
| `get()[0].name` | 字段(下标(调用)) | 后缀链的先后顺序 |

## 3. 验证覆盖

- 原 Lexer 自动化测试105项保持通过。
- Parser 新增23个测试方法，包括类型声明、AST 形状、优先级、结构上下文、诊断位置、命令行和策略开关。
- 上一阶段70个 LALR 语法审查案例再次逐项运行，含29个语法允许、29个语法拒绝、4个结构上下文拒绝、8个语法可接受但应由语义检查处理的案例。
- 70项复核集中在一个 unittest 测试方法中，以 subTest 的方式逐例报告，因此整体 unittest 数量为128，而不是198。

## 4. 阶段边界

Lexer：识别 Token、字符串转义、非法数字与编码。Parser：构建 AST、拒绝语法错误、执行前结构上下文检查。注册/运行阶段：校验名称、类型、可调用性、结构体字段、数组元素类型与空数组类型上下文、递归上限和计算行为。

包括 `print([])`、`let print: int = 2;`、`int + float` 和 `1e309` 在内的程序可能通过 Parser，但它们之后必须由语义/运行期按相应规则拒绝。

## 5. 未批准的语法边界

- `struct Empty {}`：采用显式配置 `allow_empty_structs`，默认保守拒绝；不表示语言设计否决该写法。
- `print(1,)`、`[1,]`、`Student {x: 1,}` 和形参尾随逗号：配置 `allow_trailing_commas`，默认保守拒绝；不表示语言设计已否决尾随逗号。
- 当前 `CallStmt` 只允许语法形态 `Identifier(...) ;`，完整一等函数/方法调用不在 V1.0 现有范围；可通过表达式中的后缀调用 AST 表示候选操作，合法性由后续阶段判断。
- 具体 `SyntaxError` 格式目前包含文件名、行、列、原因；源码指示符和栈诊断留给后续统一诊断模块。
