# ZBY V0.2 Interpreter 阶段一实现审查

> 本文记录实际原型实现与已认可设计的符合范围；示例测试不作为未实现功能已经完成的证据。

## 架构

原有 `Lexer → Parser → AST` 管线未更改语法入口；新加 `Interpreter` 使用 AST 节点执行顶层语句。`run(source)` 在创建运行时之前完整解析整个源码，避免后段语法错误导致前段语句被执行。

`Scope` 支持词法嵌套环境；函数本地作用域以全局作用域为父作用域，而非调用者局部作用域，以防止意外动态作用域。变量用 `Binding(type_name,value)` 保留声明类型和当前值。

| 决策 | 对应行为 | 核心测试 |

| DD-009～DD-011 | 类型声明与运行时类型检查，无隐式转换 | `int` 变量不能绑定 `string`；`int + float` 报错 |

## 已知实现差距

1. **复合类型全线未运行化：** 数组/结构体/共享引用/深拷贝/复合打印仍须实现；`PrototypeLimitError` 是原型特有的实现进度标识，不是新增 ZBY 正式错误类别。
2. **复杂赋值目标：** Parser 已识别复合左值；Interpreter 尚无目标对象定位、右值副作用后再校验逻辑。
3. **资源限制：** 任意精度整数的字符串转换已避免宿主默认十进制数字数量限制，但仍可能因内存等实际资源限制失败；极端容量需后续压力测试。
4. **诊断格式：** 当前输出文件:行:列:类别:原因，并显示调用路径，尚未渲染源码行和光标；ZBY 诊断完整格式尚待完善。
5. **函数参数：** 目前只支持基本类型及基本类型返回；将来应复用同一按数量先检查、然后从左到右逐项求值与类型校验的执行机制，不另建一套行为。
6. **float 文本：** `repr` 实现最短回读常见场景，跨平台字节级规范需最终金标准；异常数值应在运行期拦截。
7. **未确定的语法：** 空结构体与尾随逗号保留为单独待决事项，不因原型默认拒绝而自动否决。

## 验证

执行：

```bash
PYTHONPATH=src python -m unittest discover -s tests -v
```

预计测试：128项既有 Lexer/Parser 测试与54项新增 Interpreter 测试，共182项。70个历史语法案例由既有 parser 单测读取并通过子测试验证。

运行演示：

```bash
PYTHONPATH=src python -m zby.interpreter examples/runtime_demo.zby
```

对实际执行结果、stdout/stderr、进程退出码分别检查。原型独立包不等于已与远端仓库源代码合并。
