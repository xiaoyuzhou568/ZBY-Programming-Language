
# ZBY 核心设计理念与设计原则

## 一、核心设计理念

### 1. 简洁性（Simplicity）

ZBY 希望降低编程语言本身的学习和使用成本。

具体要求：

- 精简语言关键字和语法规则。
- 同一功能尽量只提供一种标准写法。
- 使用统一的代码块组织形式。
- 避免引入不必要的复杂机制。
- 保持代码结构清晰，便于阅读。

### 2. 明确性（Explicitness）

ZBY 强调程序结构和行为的明确性，减少隐藏规则和不确定性。

具体要求：

- 变量具有明确的数据类型。
- 函数参数和返回值具有明确的类型声明。
- 类型转换采用显式方式。
- 运算规则和执行顺序具有明确规定。
- 对不符合规则的操作进行检查。

### 3. 可解释性（Explainability）

ZBY 不仅要求程序能够执行，还希望使用者能够理解程序的错误和运行行为。

具体要求：

- 区分不同类型的错误。
- 尽可能提供错误所在的行号和列号。
- 说明预期类型与实际类型。
- 提供清晰的错误原因。
- 在适当情况下给出修正建议。

## 二、语言设计原则

### P1：语法统一

同一种功能尽量只提供一种标准语法，避免不必要的表达方式重复。

### P2：类型明确

变量、函数参数和返回值应具有明确的类型声明。

### P3：转换显式

不依赖隐式类型转换，重要的类型变化应当能够在代码中直接观察。

### P4：结构清晰

使用统一的代码块组织方式，保持程序结构易于识别。

### P5：语义确定

对运算符、表达式、作用域和程序执行顺序制定明确规则。

### P6：安全运行

对数组越界、除零和非法类型转换等常见错误进行检查。

### P7：错误可诊断

错误信息应尽可能包含位置、错误类型和具体原因。

### P8：便于协作

建立标准化的语言规范、开发文档和代码示例，使人类开发者与 AI Agent 能够使用同一套规则进行开发。

## 三、设计取舍

ZBY 不以功能数量作为语言设计的主要目标。

对于新增功能，应当综合考虑：

- 是否具有实际使用价值。
- 是否符合核心设计理念。
- 是否会显著增加语言复杂度。
- 是否容易实现和测试。
- 是否有利于人类与 AI 协作开发。

对于收益不明确、实现成本过高的功能，优先考虑暂不纳入当前版本。

## 四、总体目标

通过简洁、明确、可解释的语言设计，建立一套适合初学者与 AI Agent 协作开发的轻量级解释型脚本语言。
